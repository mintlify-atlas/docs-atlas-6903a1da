T.O.P ships a curated catalogue of over 300 browser games and a separate catalogue of web apps, all accessible without leaving the proxy. Games are found at `/games` and apps at `/apps`. Both pages load their content from local JSON files, render a card grid in the browser, and route clicks through the same proxy engine used for manual URL navigation.

## Catalogue files

The two catalogues are stored as minified JSON arrays and fetched by `launcher.js` at page load:

| File | Route | Contents |
|---|---|---|
| `static/assets/json/games.min.json` | `/games` | 300+ browser games |
| `static/assets/json/apps.min.json` | `/apps` | Web apps, social, media, and emulators |

Each entry carries a `name`, an `image` path, a `link` (or `links` array for multi-region titles), and a `categories` array used by the filter dropdown. In production builds the catalogue payload is XOR-encoded and decoded client-side using a per-build key so the listing is not trivially scraped.

```json
{
  "name": "Slope",
  "link": "https://watchdocumentaries.com/wp-content/uploads/games/slope/",
  "image": "/assets/media/icons/slope.webp",
  "categories": ["all"]
}
```

## Search and filtering

Both pages share the same filter logic implemented in `launcher.js`. The search input and category dropdown call `applyFilters()`, which hides any card whose name does not match the search term or whose category list does not include the selected value.

```js
// launcher.js — filter logic
function applyFilters() {
  const searchTerm = (document.getElementById("search")?.value ?? "").toLowerCase();
  const selectedCategories = Array.from(
    document.querySelectorAll("#category option:checked")
  ).map(option => option.value);

  Array.from(document.getElementsByClassName("column")).forEach(card => {
    const appName = card.getElementsByTagName("p")[0].textContent.toLowerCase();
    const categories = card.getAttribute("data-category").split(" ");

    const matchesSearch = !searchTerm || appName.includes(searchTerm);
    const matchesCategory =
      selectedCategories.length === 0 ||
      selectedCategories.some(cat => categories.includes(cat));

    card.style.display = matchesSearch && matchesCategory ? "block" : "none";
  });
}
```

## Pinning games and apps

Any card (except the two special cards at the top of each page) can be pinned. Clicking the pin button on a card moves it into the pinned section above the main grid. Pins are stored in `localStorage` per-page (`Gpinned` for games, `Apinned` for apps) so they survive page reloads.

## GitHub game asset proxy (`/gh-games`)

Some games in the catalogue are hosted on GitHub and served through T.O.P's own asset proxy at `/gh-games/:path` rather than directly from `raw.githubusercontent.com`. This reduces direct client-to-GitHub traffic and allows the server to apply long-lived caching headers.

Four GitHub repositories are mirrored:

```js
// src/games.js
const ghGamesBases = {
  "/gh-games/1/": "https://raw.githubusercontent.com/qrs/x/fixy/",
  "/gh-games/2/": "https://raw.githubusercontent.com/3v1/V5-Assets/main/",
  "/gh-games/3/": "https://raw.githubusercontent.com/3v1/V5-Retro/master/",
  "/gh-games/4/": "https://raw.githubusercontent.com/xbubbo/V6-Assets/main/",
};
```

The proxy forwards `If-None-Match` headers from the browser and passes `ETag` and `Last-Modified` headers back so conditional requests work correctly. Every successful asset response is served with a one-year immutable cache header:

```js
res.writeHead(200, {
  "Content-Type": contentType,
  "Cache-Control": "public, max-age=31536000, immutable",
  ...(etag && { ETag: etag }),
  ...(lastModified && { "Last-Modified": lastModified }),
});
```

The `/gh-games` route is rate-limited to **50 requests per minute** per IP.

<Note>
  Game assets fetched through `/gh-games` are cached by the browser for a full year (`max-age=31536000, immutable`). After the first load, subsequent visits to the same game will be served entirely from the browser cache with no network round-trip to the server or GitHub.
</Note>
