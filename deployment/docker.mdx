T.O.P ships with a ready-to-use `Dockerfile` based on the slim Debian Bookworm Node.js image. Containerising the proxy keeps it isolated from the host system and makes it straightforward to deploy anywhere that runs Docker — including cloud platforms such as Render.

## The Dockerfile

The project's `Dockerfile` is reproduced in full below. It sets `NODE_ENV` to `production`, copies `package.json` first to take advantage of Docker's layer cache, installs dependencies with npm, copies the rest of the source, and launches the server directly with `node`.

```dockerfile
FROM node:bookworm-slim
ENV NODE_ENV=production

WORKDIR /app

COPY ["package.json", "./"]

RUN npm install

COPY . .

CMD [ "node", "src/server.js" ]
```

<Note>
  `NODE_ENV` is set to `production` inside the image. This means development-only dependencies are not installed and Node.js runs with production optimisations enabled.
</Note>

## Building the Image

Run the following command from the root of the repository to build a local Docker image tagged `interstellar`:

```bash
docker build -t interstellar .
```

## Running the Container

### Default (port 8080)

Start a container and map host port `8080` to the container's port `8080`:

```bash
docker run -p 8080:8080 interstellar
```

### Custom PORT

To make the server listen on a different port inside the container, pass the `PORT` environment variable and update the port mapping to match:

```bash
docker run -p 3000:3000 -e PORT=3000 interstellar
```

Both the `-p` host-side mapping and `-e PORT` must use the same port number so that the server binds to the port Docker is forwarding.

## Password Protection

T.O.P supports optional password protection controlled by the `challenge` flag in `config.js`. To enable it, open `config.js` and set `challenge` to `true` **before** building the Docker image:

```javascript
const config = {
  challenge: true,
  users: {
    interstellar: "password",
  },
};
```

After saving the file, rebuild the image so the updated `config.js` is baked in:

```bash
docker build -t interstellar .
docker run -p 8080:8080 interstellar
```

<Note>
  Password protection is configured at build time by editing `config.js` — there is no runtime environment variable that toggles it. If you change `config.js` after building, you must rebuild the image for the change to take effect.
</Note>

## Deploying to Render with Docker

The repository includes a `render.yaml` that configures a Render web service using the Docker environment:

```yaml
services:
  - type: web
    name: edu
    env: docker
    plan: free
```

Render automatically detects this file when you add the repository as a new web service. Because `env` is set to `docker`, Render will build the image from the project's `Dockerfile` rather than using a managed runtime. See the [Cloud Platforms](/deployment/cloud-platforms) page for the full Render setup walkthrough.
